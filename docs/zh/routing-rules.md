# 路由规则

路由规则限制 **proxy 仓库**可以提供的请求路径，可用于阻止内部命名空间访问公共上游，或只允许指定路径。

1. 打开 **Repository → Routing Rules**，创建规则。
2. 选择 BLOCK（阻止匹配路径）或 ALLOW（只允许匹配路径）。
3. 每行填写一个 Java 正则表达式。表达式匹配完整的仓库相对路径，包含开头的 `/` 和查询参数；任意一个表达式匹配即生效。
4. 使用 **Test path** 验证示例路径，然后保存。
5. 编辑 proxy 仓库，在 **Proxy settings → Routing Rule** 中选择规则。

例如 BLOCK 规则 `/com/company/.*` 可阻止 Maven 代理提供该命名空间。一个规则可以被多个 proxy 仓库共用，每个 proxy 只能绑定一个规则。修改规则会影响所有已绑定仓库；删除规则前必须解除全部绑定。

被阻止的直接代理读取返回 HTTP 403，已经缓存的内容同样受限。通过 group 访问时，会跳过被阻止的代理成员，按成员顺序继续查找。hosted 仓库不受影响。规则针对请求路径，不会检查漏洞，也不会从已允许访问的索引文档中删除条目。漏洞判定使用制品扫描策略，按用户授权使用内容选择器。

管理接口与 Nexus 一致：`/service/rest/v1/routing-rules` 支持 GET、POST，`/{name}` 支持 GET、PUT、DELETE。请求体示例：

```json
{"name":"block-company","description":"阻止内部命名空间","mode":"BLOCK","matchers":["/com/company/.*"]}
```

新增、修改、删除成功返回 204；正则错误、删除已绑定规则返回 400。管理操作需要 `nexus:*` 管理权限。仓库配置接口 `/internal/repositories` 使用 `routingRuleName` 字段，也接受旧版 Nexus 的 `routingRule` 名称。空字符串解除绑定；部分更新时省略字段会保留原绑定。

规则及绑定保存在共享数据库中。每次请求在访问协议缓存前读取一致的策略快照；group 缓存版本包含规则和实际可用成员，避免旧缓存绕过规则。已经开始处理的请求继续使用自己的快照。

参见[兼容性映射与测试说明](../../compat-test/routing-rules-mapping.md)。Nexus 3 配置迁移会导入路由规则，并恢复受支持代理仓库的绑定。预检查展示规则、绑定、阻塞原因和源策略的 SHA-256 校验值，兼容源配置中的 `routingRule` 和 `routingRuleName` 字段。

同名且内容一致的规则直接复用；同名内容冲突、规则缺失、正则无效或源规则 API 不可读时，阻止配置迁移。不会静默替换或移除目标仓库已有的不同规则绑定，需要先明确处理冲突再重试。规则与仓库配置在同一数据库事务中写入，结果报告校验规则内容及绑定。重复迁移复用规则 ID；并发创建冲突会回滚，可重新执行，已有规则和仓库绑定通过数据库行锁协调多副本写入。

源账号需要具有规则 API 的访问权限。此步骤迁移配置，不复制缓存制品文件；仓库数据迁移仍是单独的步骤。
